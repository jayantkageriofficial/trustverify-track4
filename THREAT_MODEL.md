# One-page threat model — TrustVerify

**Scope and assets.** Organizer-owned loopback mock services, synthetic users and files only. Protect message/file plaintext, endpoint identity and ephemeral keys, local inbox storage key, registry ownership, service permissions, revocation tombstones, committed key versions, authority backup material and the actor/action/boundary of key/access events.

**Attackers.** A malicious enrolled user, a holder of a stolen/revoked test-device credential, a client replaying or altering requests/fragments/recipient metadata, an attacker injecting log text, and someone altering an exported audit log or backup without the signing/recovery keys. Faults include node interruption, either rotation commit boundary, corrupted backup, lost device, fragment loss/reordering and differing source clocks.

**Trust boundaries.** Endpoint plaintext/ephemeral secrets stay outside relay/authority storage. Node HTTP input is lower trust than the registry. Identity/role/permission decisions are authoritative, not supplied by the caller. Structured user text cannot write actor/action fields. Verification trusts separately retained public roots/checkpoints, not data bundled with the log. Backup bytes are unauthenticated until the complete AES-GCM tag and pinned state checks pass.

**Assumptions.** The OS, endpoint process memory while in use, trusted authority host clock, application code and crypto library are trusted. Operator bootstrap/enrolment is authorized out of band, and the two administrator identities belong to different people; role assignment is not an anonymous signup. Directory/public-key roots are pinned. Authority and operator directories have separate logical ownership; the local demo uses one OS account, so this is not hardware isolation. Operators retain the recovery key and latest signed checkpoint outside authority failure storage. Clock-offset metadata is supplied by a trusted collector.

**Controls.** ML-DSA-65 authentication; library ML-KEM-768/X25519 HPKE and AES-GCM; signed one-use recipient offers and manifests; transactionally consumed node-bound challenges; per-request revocation/permission checks; atomic lifecycle/audit commits; permanent tombstones; verified fresh backups; signed hash-linked logs and external checkpoints; bounded fragment recovery and authenticated complete-message delivery; durable replay records; two-person approval for privilege grants; summarised and throttled unauthenticated failures; stateless library-signed challenges that allocate no issuance rows or evict pending tokens, with a persistent consumed-token cache and restore epoch; authenticated directory lookups; context-aware privilege/revocation/service-transition/self-approval rules with a live watch mode with durable handled-record hashes and atomic checks that skip superseded permissions; a learned per-role edge baseline; a pqcrypto-only grader adapter with ML-KEM-768 protected reads, an ML-DSA-65 signed audit, an HMAC-tagged state file, fail-closed replies for every malformed or tampered request, a refused planted temp directory and signed alerts for probing denials that name the identity, service, events, rule and explanation; every alert tagged with its closest MITRE ATT&CK technique; threaded mock-service nodes with a connection cap so stalled clients cannot block service; bounded event-time ordering with uncertainty notices.

**Failure behavior.** No admission grace after rotation commit; existing transfers retain a 120-second grant unless revocation or permission loss overrides it. Authority outages fail closed. Recovery selects the last committed authenticated version. Damaged backups fail before key use; an older verified backup needs explicit, logged rollback, re-applies signed revocations, and is refused if it predates a retained key rotation. Signed restore intent lets recovery retain the previous state or finish an interrupted replacement. Adapter MAC migration retains a protected intent for the exact legacy snapshot, verifies its setup and history, and recovers interrupted publication before serving requests. Early malformed-input alerts are written only to verified history; capacity rejection is a JSON 503. Legacy nonce tables migrate without changing committed keys or data; a fresh challenge epoch rejects pre-restore requests. Incomplete/invalid sessions are discarded; a new handshake is required. Completed deliveries remain in a separately encrypted local inbox.

**Limits and residual risk.** No protection against a privileged host attacker, malicious trusted operator, live endpoint-memory compromise, compromised library, stolen recovery/checkpoint roots, or plaintext already copied by an authorized recipient. Python cannot promise physical key zeroization. No resumption, post-compromise healing, replicated authority, production TLS deployment, audit-key rotation or general-purpose UEBA. Truncation before the first retained checkpoint and an unacknowledged/uncheckpointed crash tail cannot be independently disproved. Simultaneously rolling back the authority and all independent operator references defeats freshness detection. Revocation across nodes is one shared SQLite authority read by three processes, not replication. The audit signing key is stored beside the database; external checkpoints and tombstones expose tampering. The grader adapter enforces a reduced policy (ownership, disable, revoke) and trusts the caller-supplied actor and an unauthenticated setup, as adapter v1 defines them; its bodies are protected at rest by file permissions and setup signatures verified against the public key retained with the protected private key, because the judging runtime has no vetted symmetric cipher, and its audit log is anchored only when the operator pins the key fingerprint returned by setup. Source-clock bounds are ±120 seconds with 30 seconds of corrected lateness; unsupported/ambiguous order is flagged. Path alerts for an uncertain identity are withheld for the whole analysis batch, reducing coverage; privilege/revocation checks remain active. Synthetic F1 is not a real-world detection guarantee: the held-out set scores 0.78 with known misses (approved-edge insider access, lateral moves slower than 60 seconds), and the 22-event practice result is a functional check only.

**Evidence.** `tests/` exercises authorization, all-node cutoff/revocation, real process crashes, corruption/stale restore, log injection/tampering, peer binding/replays, incomplete/reordered delivery, clock uncertainty and contextual detections. `reports/demo.json` records actual local measurements; `reports/detector.json`, `heldout.json` and `practice.json` record event-level detection results on rule-aligned, held-out and toolkit practice data.
